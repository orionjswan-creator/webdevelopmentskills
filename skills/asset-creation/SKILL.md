# Asset Creation

You produce the complete visual inventory for a website: everything code can make, you make now;
everything that needs an image/3D/video model, you spec so precisely that the user (or another
agent) can generate it in one shot. The single source of truth is **`assets/manifest.md`** — the
site-builder skill wires every visual slot to a manifest ID, so your IDs and paths are a contract.

## Inputs

1. `BRIEF.md` and `DIRECTION.md` if they exist (from site-builder) — read them first
2. The chosen style skill in `skills/styles/` — its "asset slots" table is your starting inventory
3. Existing site code, if any — grep for `data-asset`, `manifest`, and image paths to find slots

If none exist, derive the inventory from the user's description of the site, then interview
(step 5) to fill gaps.

## Workflow

### 1. Establish art direction

Write (or extend) the **art-direction block** at the top of the manifest — one shared style
definition every image prompt inherits. This is what makes 20 generated images look like one
photographer/illustrator made them, which is the difference between "award site" and "AI collage":

```md
## Art direction
- Medium: <e.g. 35mm editorial photography | 3D clay render | flat vector illustration>
- Palette: <hex values from DIRECTION.md — name them in prompts as colors, not hex>
- Lighting: <e.g. soft north-window light, deep shadows>
- Mood: <3 adjectives, same set as DIRECTION.md>
- Composition: <e.g. generous negative space, subjects off-center right>
- Always exclude: <e.g. text, watermarks, people's faces, busy backgrounds>
```

### 2. Build the asset inventory

List every asset the site needs, categorized:

| Category | Examples | Route |
|---|---|---|
| **Code-producible** | logo/wordmark, icon set, noise/grain, gradient meshes, dividers, patterns, favicons, OG template, shader backgrounds, loading animations | You generate these NOW — recipes in `references/code-assets.md` |
| **Image-model** | hero photography/renders, product shots, portraits, illustrations, textures with subject matter | Manifest entry with full prompt spec — tool matrix in `references/ai-image-tools.md` |
| **3D-model** | glTF hero objects, product models | Spec for Meshy/Tripo (or mark for a 3D artist) |
| **Video/audio** | loops, ambient sound | Spec for Runway/Sora/Veo, ElevenLabs — only if the style skill calls for them |
| **User-supplied** | real product photos, team headshots, existing logo | Manifest entry with `status: awaiting-user` + exact size/format requirements |

Never route to an image model what code does better: gradients, geometric patterns, UI mockups,
anything with text (code renders text perfectly; image models still fumble it — if text-in-image
is unavoidable, Ideogram is the tool).

### 3. Generate all code assets

Follow `references/code-assets.md`. Deliverables: `assets/svg/` (logo, icons), `assets/textures/`
(grain, patterns), `assets/scripts/` (OG-image generator, favicon pipeline, placeholder
generator), everything committed and referenced by manifest ID.

### 4. Write the manifest

Format in `references/asset-manifest-template.md`. Every entry gets: `id`, `path`, `dimensions`,
`format`, `role` (where it appears), `status` (`final` | `placeholder` | `awaiting-user` |
`todo-describe`), `alt` text, and — for image-model assets — a **prompt spec**: recommended tool,
full prompt (inheriting the art-direction block), negative/exclusions, aspect ratio, and any
tool-specific parameters. A person with zero context should be able to paste the prompt into the
named tool and get a usable result first try.

### 5. Interview the user (the "ask for what needs to be made" step)

Batch your questions — ONE round, maximum ~6 questions, only things you genuinely cannot infer:

- Does a logo exist, or do you want a code-built wordmark? (If exists: request the file)
- What do the hero and key section images actually depict? (subject matter is yours to ask,
  style is already fixed by the art-direction block)
- Real photos of product/team/space available, or generate everything?
- Any assets with hard requirements (press photos, certification badges, partner logos)?

**If the user is unavailable or doesn't answer**: do not stall. Fill each unknown with your best
inference marked `status: todo-describe` and a `TODO(describe: <what you need to know>)` line in
the prompt slot, then continue. The manifest is designed to be revised.

### 6. Generate placeholders

Run the placeholder generator (`references/code-assets.md §7`) so a labeled SVG exists at every
manifest path with the exact target dimensions. The site must build and look intentional —
placeholders carry the palette, the asset ID, and dimensions.

### 7. Hand off

Append a **Generation guide** section to the manifest: for each pending asset, the tool to open,
the prompt to paste, the export settings (2× target size, then compress to AVIF/WebP ≤ 200KB via
the provided `sharp` script), and the exact path to save to. End by listing: assets finalized,
assets awaiting generation, assets awaiting the user.

## Prompting THIS skill from Codex (copy-paste for users)

```text
Read skills/asset-creation/SKILL.md and follow it exactly, including its references.
Project: <one-line description or "see BRIEF.md">.
Style: skills/styles/<style-name>/SKILL.md.
Site code (if any): <path>.
Ask me your interview questions first in one batch; then generate all code assets,
write assets/manifest.md with prompt specs, and create placeholders at every path.
```

For a fully autonomous run (no interview): append
`Do not wait for my answers — use todo-describe slots and finish.`
